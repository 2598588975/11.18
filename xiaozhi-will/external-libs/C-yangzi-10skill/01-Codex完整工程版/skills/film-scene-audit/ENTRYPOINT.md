# 洋子 · 剧本压力测试

在投入图像和视频制作前，检查一场戏或一个序列的因果链。本模块是结构诊断，不新增电影创作阶段；可独立调用，也可由 04 分场、05 剧本或 08 拆镜前调用。采用用户补充包中的专用定义，不把它们偷换成通用编剧术语。

## 输入与范围

读取用户指定的场景/序列及必要的故事总目标、前置事实。项目模式以最新确认稿为依据，记录文件、版本和场号；独立片段可直接审查，不强迫初始化全流程。

先明确审查单位：单场戏，还是从特定危机出现到被解决/失败并转向的完整序列。序列可以嵌套，分别标明层级。总目标未知时只询问这一缺项；仍可先检查局部障碍、策略和已展示的变化，但不能宣称完整因果链通过。序列结尾未提供时，逆转判为“暂不可判”，不能因一个升级场没有反转就判失败。

## 五要素的专用定义

1. **目标 Goal**：在本引擎内，总目标是主角努力修复已建立问题的单一、不变诉求；可以选错策略，不把目标本身当作策略错误。每场目标必须是通向总目标的因果环节。做删除测试：拿掉这一场，因果链仍完整，则指出该场的结构必要性不足。若作品刻意采用目标重置、群像多线或非因果叙事，声明此模型的适用范围，不自动把作品改成单主角固定目标故事。
2. **障碍 Obstacle**：会威胁某一步或整个目标实现的强情境，须写清“什么面临失败＋局部/全局尺度”。仅增加花费、难度或气氛不等于形成威胁。障碍可来自多分支搜索，也可是一堵硬墙；它必须迫使人物选择或改变策略。
3. **策略 Tactic**：人物基于当时有限信息，被威胁迫使采用的合理尝试。判断依据是当时知道什么，不用事后全知视角骂人物愚蠢。失败必须返回新信息、缩小搜索范围并影响下一步；没有依据的尝试或失败后零信息的重复消耗，才是空转。另查行为与赌注是否相称，区分写作矛盾与有证据的自我破坏。
4. **逆转 Reversal**：行动结果背离原意；可为自己的行动反噬、被作用对象其实一直在反向操控自己，或结果与策略预期相反。每个已解决的序列至少一次；单场可只负责升级，不要求每场强塞反转。
5. **价值变化 Value Shift**：逆转触发观众重新评价人物，是“观众原先怎么看这个人 → 现在怎么看”，不是贫富、输赢、生死等外部处境翻转，也不是角色当下的情绪。每次逆转必须写出评价前后及其可见证据；只有剧情翻转、人物评价不动，标记“无效逆转 INERT”。最后检查这些重估是否逐步深化人物，还是来回摆动。

因果链：目标 → 受到威胁 → 被迫选择合理策略 → 得到信息/发生逆转 → 观众重新判断人物。优先找“情节翻了，但观众对人物的看法没有改变”的问题。

## 交付

用中文，给证据与短判断，不输出冗长推演：

```text
审查对象、输入版本与范围：
序列边界/完整性：
目标：场景目标、总目标联系、删除测试、结论
障碍：威胁什么、局部/全局、结论
策略：当时信息、尝试依据、返回信息、下一步
逆转：位置、类型、所属序列、结论
人物评价变化：每次逆转的之前 → 之后、证据；或 INERT/暂不可判
最弱环节：只指出修复收益最高的一处
方案一·最小修复：仅修该处，保留其余已定事实
方案二·完整修复：更大调整及影响范围
方案三·可选：确有不同收益时才给
```

建议中新增的情节必须标为候选。诊断或“更有张力”的请求不自动授权改掉已锁定场次、人物、对白与结局。用户明确要求修订时交给当前故事阶段执行其版本与范围规则；压力测试不直接写上游文件，也不自动触发资产/视频重生成。

独立调用默认在聊天完整交付；项目调用另存 `02_script/scene-audit-<场次或序列ID>-vNNN.md`，记录证据与建议状态，不更改路由的当前创作阶段。审计报告确认不等于候选修改获准，也不使下游过期；只有修订后的权威输入确认时才按真实依赖更新。
